## Why this exists

The fleet's stack docs already cover what we *use* (FastAPI, Pydantic, SQLAlchemy,
Qdrant, Nuxt, LiteLLM, PTB). Two gaps were measurable in the 2026-09-28 coverage audit:

1. **the protocols we build against** — x402 (payment gate) and MCP (tool surface every
   agent speaks) had no corpus presence at all;
2. **design reasoning** — `research_v2` held 158 points against a 2.13M code corpus
   (0.0074%), the largest structural imbalance in the fleet. Specs state what is
   required; they never state what broke in production or why the alternative was
   rejected. That lives in engineering writing.

Placement follows `DATA-PLACEMENT.md`: **knowledge → RAG, code → MCP.** Nothing here is
source code; `sourcify_contracts` and `codebase_reference_v2` own that side.

## Collections: reused, not forked

`rag_documents_8b` (1.17M pts, live) and `research_v2_8b` (164 pts, live) are the
4096 write lanes of collections that **already exist**. Devdocs go there under
`metadata.ingest_group="devdocs"` and `metadata.family`, so they are filterable without a
new collection competing in every top-k cut.

The `_8b` suffix is deliberate: the base names (`rag_documents` 667K, `research_v2`) are
the retired 2560 generations, so a 4096 write there is refused by the dimension guard.
That refusal is correct — see `DUAL_TIER_RAG.md`. No new collection was declared, so
`corpus/entries.py` is unchanged.
